# BLUE IMMERSION — 아키텍처 & 화면 설계 (Phase 1)

> 원칙: 기능 수보다 **물 · 빛 · 산호 · 생물의 움직임** 완성도. 모든 단계는 브라우저에서 바로 실행 가능한 상태를 유지한다.

---

## 1. 기술 선택과 이유

| 영역 | 선택 | 이유 |
|---|---|---|
| 빌드 | Vite + TypeScript | 빠른 HMR, 단일 HTML 빌드(`vite-plugin-singlefile`)로 설치 없이 배포 |
| 3D | **Three.js (vanilla)** | 물·커스틱·빛줄기는 대부분 **커스텀 셰이더**. 렌더 루프와 인스턴싱을 직접 제어해야 모바일 프레임을 지킬 수 있음. R3F는 UI 많은 앱에 강점이지만, 이 프로젝트의 핵심(셰이더+시뮬레이션)에는 추상화 비용만 늘어남 |
| UI | 경량 DOM 오버레이 (프레임워크 없음) | 3D 위에 얹는 반투명 UI 몇 개뿐. 추후 React로 교체해도 `store` 구독 구조라 3D 코드는 영향 없음 |
| 상태 | 자체 `store` (Zustand와 동일한 subscribe 패턴) | 의존성 최소. 필요 시 Zustand로 1:1 치환 가능 |
| 사운드 | Web Audio API **절차적 합성** | 에셋 없이도 파도·바람·엔진·호흡·기포·딱총새우 크래클 재생. 최종 녹음 에셋이 들어오면 같은 채널로 교체 |
| 물리 | 자체 경량 처리 (지형 높이 충돌, 중성부력 감쇠) | Rapier는 캐릭터-산호 충돌이 필요해지는 Phase 7에서 검토 |
| 멀티플레이 | 미구현, **세션/월드 분리 구조**만 준비 | `WorldSession`(배·지역 단위) ↔ `LocalPlayer` 분리 → 이후 WebSocket 동기화 계층 추가 |

## 2. 전체 구조

```
src/
├─ main.ts                    부트스트랩
├─ core/
│  ├─ Engine.ts               렌더러·씬·카메라·루프·후처리(톤매핑/수중 왜곡/비네트)
│  ├─ quality.ts              PC/모바일 품질 티어 자동 결정
│  └─ store.ts                전역 상태(phase, mode, 설정) + subscribe
├─ water/                     ★ 최우선 품질 영역
│  ├─ WaterShading.ts         모든 머티리얼 공통 패치: 수심별 흡수(빨강부터 사라짐),
│  │                          거리 산란, 커스틱, 수면 위에서 본 수중 경로 보정
│  ├─ OceanSurface.ts         Gerstner 파도(GPU+CPU 동일 함수), 수면 위/아래 셰이딩,
│  │                          스넬의 창·전반사, 리프 위 청록색 틴트(지형 깊이 텍스처)
│  ├─ Sky.ts                  하늘 돔 + 태양 + 구름
│  ├─ LightShafts.ts          수면 아래로 내려오는 빛줄기(인스턴싱 빌보드)
│  ├─ Particles.ts            부유 입자(햇빛 받으면 반짝임)
│  └─ Environment.ts          카메라 수심에 따른 조명·물색·안개 오케스트레이션
├─ world/
│  ├─ terrain.ts              해저 높이 함수 + 서식지 샘플링(산호/모래/해초/개방수역)
│  ├─ Seabed.ts               해저 메시(모래 물결 무늬, 암반)
│  ├─ CoralReef.ts            산호 7계열 절차 생성 + 수심별 배치 + 해류 흔들림
│  ├─ Residents.ts            고착/정주 생물: 말미잘+흰동가리, 자이언트 클램, 성게,
│  │                          해삼, 불가사리, 해초, 곰치
│  └─ Boat.ts                 선체, 스노클링 계단(우현), 다이빙 플랫폼(선미), 장비 점검대
├─ life/
│  ├─ species.json            ★ 생물 데이터 (코드와 분리)
│  ├─ FishBody.ts             종별 체형 파라미터 → 지오메트리, 꼬리 파동 셰이더, 무늬
│  ├─ FishSystem.ts           종별 InstancedMesh + 행동(군집/배회/섭식/말미잘/순항/정지)
│  ├─ Megafauna.ts            바다거북·만타·가오리 (전용 지오메트리·애니메이션)
│  └─ SpawnDirector.ts        서식지×수심×확률×최근출현 패널티×크기별 예산
├─ character/
│  ├─ Diver.ts                관절 계층 캐릭터 + 절차적 포즈(서기/걷기/엎드려 유영/호버링/입수)
│  └─ Gear.ts                 장비 슬롯(머리·얼굴·입·등·허리·손목·발) 부착/탈착
├─ control/
│  ├─ Input.ts                키보드·마우스·터치 → 하나의 InputState로 정규화
│  ├─ TouchControls.ts        가상 조이스틱 / 카메라 드래그 영역 / 활동별 버튼 (멀티터치)
│  ├─ CameraRig.ts            3인칭 오빗(회전 제한·감쇠·지형/수면 충돌), 1인칭 확장 지점
│  ├─ SnorkelController.ts    수면 부유 ↔ 덕다이브 ↔ 자동 복귀
│  └─ ScubaController.ts      3D 유영, 중성부력, 상승/하강 속도 제한, 이퀄라이징
├─ dive/DiveComputer.ts       수심·시간·잔압(SAC 기반)·수온·상승속도·NDL·안전정지
├─ flow/Flow.ts               체험 흐름 상태머신 + 연출(카메라/배/캐릭터 시퀀스)
├─ audio/Audio.ts             채널(전체/환경/생물/장비/음악) 절차적 사운드
└─ ui/                        HUD, 선택 카드, 장비 착용 단계, 입수 전 점검, 설정
```

### 확장 포인트 (지금은 구현하지 않지만 구조로 보장)
- **여러 환경**: `terrain.ts`, `CoralReef`, `species.json`이 `RegionConfig` 하나로 묶임 → 켈프숲·블루워터 등 새 환경은 config 추가.
- **여러 배 / 멀티플레이**: `Boat`는 `BoatConfig`(정원, 지역 ID)로 생성. `Flow`는 로컬 플레이어 상태만 다루고, 다른 플레이어는 `RemoteDiver`(같은 `Diver` 클래스 재사용)로 추가.
- **캐릭터 커스터마이징**: `Diver`의 색/체형 파라미터 + `Gear` 슬롯 시스템.
- **도감·발견 기록·사진**: `SpawnDirector`가 이미 `onEncounter(speciesId)` 이벤트를 발행.

## 3. 체험 흐름 (상태머신)

```
 title ──탑승──▶ boarding ──▶ cruise ──(도착)──▶ anchored
                                                   │  선택: SNORKEL / SCUBA
                                                   ▼
                                                gearing (장비 순차 착용, 스쿠버는 입수 전 점검)
                                                   ▼
                                                 entry  (스노클=우현 계단 / 스쿠버=선미 플랫폼 자이언트 스트라이드)
                                                   ▼
                                                 swim   (자유 유영, 시간제한·미션 없음)
                                                   │  배로 복귀
                                                   ▼
                                               anchored (장비 해제 → 다른 체험 선택 가능)
```

각 phase는 `enter / update / exit`를 가지며, UI는 `store.phase`만 구독한다.

## 4. 화면 구성

### 4-1. 첫 화면 (title)
```
┌──────────────────────────────────────────────┐
│ 하늘·구름                                     │
│ ───────────── 수평선 ─────────────            │
│        BLUE IMMERSION                         │
│   바다로 들어가는 작은 휴식처                    │
│                ⛵ (파도에 흔들리는 배)          │
│             [ 배에 탑승하기 ]                  │
│ 🔊 소리 켜짐                       ⚙ 설정      │
└──────────────────────────────────────────────┘
```
### 4-2. 이동 (cruise)
배 갑판 뒤쪽 3인칭 시점 → 바다 한가운데로 이동. 깊은 남색 바다 → 리프 위 청록색으로 수면 색 변화. 항적·물보라·엔진/바람 소리. 우하단 `건너뛰기`.

### 4-3. 체험 선택 (anchored)
```
┌──────────────────────────────────────────────┐
│ ┌───────────┐                  ┌───────────┐ │
│ │ SNORKELING│   (갑판 위        │SCUBA DIVING│ │
│ │ 밝은 청록  │    수영복 캐릭터) │ 깊은 남색   │ │
│ │ 0–5m 수면 │                  │ 5–30m 3D   │ │
│ │ 우현 계단  │                  │ 선미 플랫폼 │ │
│ └───────────┘                  └───────────┘ │
└──────────────────────────────────────────────┘
```
### 4-4. 장비 착용 (gearing)
카메라가 캐릭터에 근접. 좌측에 단계 리스트(현재 단계 강조), 장비가 하나씩 부착되는 연출. 스쿠버는 수트가 발끝부터 위로 덮이는 연출 → **입수 전 점검(BWRAF + 버디)** → "가상 체험이며 실제 교육을 대체하지 않음" 안내.

### 4-5. 수중 (swim) — PC / 모바일 공통 원칙: 화면 중앙 비우기
```
┌──────────────────────────────────────────────┐
│┌DIVE────┐                         [⚙][⛵복귀]│
││ 12.4 m │ ← 스쿠버만                          │
││ 07:32  │                                    │
││ 168bar │                                    │
│└────────┘                                    │
│                (바닷속 풍경)                  │
│                                              │
│  ◯ 조이스틱                       [▲ 상승]    │
│ (모바일만)       ← 오른쪽 드래그=카메라 →  [▼ 하강] │
└──────────────────────────────────────────────┘
```
스노클링 HUD는 잠수 중일 때만 수심을 작게 표시.

## 5. 핵심 시스템 설계

### 5-1. 물 표현 파이프라인 (최우선)
1. **수심별 태양광 흡수** — 프래그먼트의 실제 수심 `d`로 `exp(-k·d)` (k: R≫G>B). 얕은 곳은 산호 본연의 색, 깊어질수록 붉은색부터 사라짐.
2. **거리 산란** — 카메라→프래그먼트 수중 경로 길이로 채널별 투과율. 물색은 수심에 따라 에메랄드 → 청록 → 코발트 → 남색.
3. **커스틱** — 태양 방향으로 투영한 월드 좌표의 절차적 패턴, 위를 향한 면에만, 수심에 따라 약화.
4. **수면(아래에서)** — 스넬의 창(약 48.6°) 안쪽은 하늘·태양, 바깥은 전반사(어두운 물색), 파도 법선으로 일렁임.
5. **수면(위에서)** — 프레넬 반사 + 투과. 지형 깊이 텍스처로 리프 위는 청록, 드롭오프는 남색.
6. **빛줄기** — 굴절된 태양 방향으로 기울어진 빌보드, 노이즈로 흔들림, 카메라 주변 재활용.
7. **부유 입자** — 카메라 주변 래핑, 빛을 받을 때 반짝임.
8. **후처리** — 미세 굴절 왜곡, ACES 톤매핑, 비네트.

### 5-2. 해양 생물
- 체형은 실제 종 비율(체고/체폭/꼬리 형태/등지느러미)을 파라미터로, 무늬는 셰이더로(흰동가리 3밴드, 무어리시 아이돌 흑백 밴드 등).
- 유영: 꼬리로 갈수록 커지는 측면 파동. 속도에 비례해 주파수·진폭 변화 → **멈추면 지느러미만 살랑**.
- 행동은 종마다 다름: `school`(분리·정렬·응집 + 동시 방향 전환 + 다이버 회피) / `wander` / `graze`(산호 쪼기) / `anemone`(말미잘 이탈 금지, 접근 시 숨기) / `cruise`(거북·상어: 옆을 지나감, 거북은 수면 호흡) / `glide`(만타: 위에서 선회) / `hover`(라이온피시) / `crevice`(곰치).
- 사용자가 멈춰 있으면 호기심 많은 종이 서서히 접근.

### 5-3. 출현 시스템 (SpawnDirector)
```
현재 위치·수심 → 서식지 판정(reef/sand/seagrass/open/wall)
 → species.json에서 서식 가능 종 필터(수심 범위, 서식지)
 → 가중치 = 기본확률 × 서식지 적합도 × 최근출현 패널티(쿨다운 동안 감소) × 희귀종 보정(오래 못 봤으면 상승)
 → 크기 등급별 동시 예산(소형 군집 / 중형 / 대형 / 메가파우나) 확인
 → 시야 밖(안개 너머 28~40m) 서식지 위치에 등장 → 체류 시간 후 자연스럽게 멀어지며 퇴장
```

### 5-4. 스노클링 vs 스쿠버 (완전히 다른 체험)
| | 스노클링 | 스쿠버다이빙 |
|---|---|---|
| 입수 | 우현 넓은 계단을 걸어 내려가 엎드려 뜸 | 선미 플랫폼, 마스크·레귤레이터 잡고 자이언트 스트라이드 |
| 기본 상태 | 수면에 엎드려 부유(파도 따라 흔들림) | 중성부력 호버링(호흡에 따라 미세 상하) |
| 수직 이동 | 잠수 버튼 누르는 동안 덕다이브, 떼면 자동 복귀 | 상승/하강 버튼, 속도 제한(상승 9m/분 기준 표시), 떼면 정지 |
| 카메라 | 수면 바로 아래, 내려다보는 시점 | 자유 3D |
| 소리 | 수면 물소리 + 바깥 소리 희미 | 레귤레이터 호흡 + 기포 + 깊이에 따른 공간감 |
| UI | 거의 없음 | 다이브 컴퓨터(수심·시간·잔압·수온·NDL·상승속도·나침반·안전정지) |
| 절차 | — | 입수 전 점검, 버디 확인, 하강 초기 이퀄라이징, 안전정지(5m 3분) |

### 5-5. 입력
- `Input`이 키보드/마우스/터치를 `{move: vec2(강도 포함), up, down, lookDelta, zoomDelta, equalize}`로 정규화 → 컨트롤러는 장치를 모름.
- 터치: 좌하단 조이스틱(놓으면 원위치), 그 외 영역 드래그 = 카메라(포인터 ID별 분리 → 멀티터치), 우하단 활동별 버튼. `touch-action:none`, 제스처/더블탭 확대 방지.

### 5-6. 성능
- 동일 종 물고기·산호·입자 전부 **InstancedMesh**, 꼬리 파동은 GPU.
- 산호는 공간 셀 단위로 묶어 프러스텀 컬링.
- 품질 티어: 모바일은 픽셀비·입자·산호 밀도·물고기 수·MSAA 축소. 안개가 시야를 자연스럽게 제한해 원거리 렌더 비용 절약.
